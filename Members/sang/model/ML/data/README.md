# Clinical ML data

The shared source of truth is `../../basic.yaml`. Clinical features and patient split assignments are read from the connected Drive paths configured there. On this PC these are `DATA/clincal/clinical_clean.csv` and `DATA/final_split.csv`; `clincal` is the actual Drive folder name. The split file uses `pid` and `split` columns, with `val` mapped to the internal `validation` split by `basic.yaml`. IDs are read as strings so leading zeros and `P` prefixes are preserved. The `SCD` column in the split file is not used as the training label; labels come from the clinical CSV. The Drive must be mounted at `/mnt/g`; these files can change independently of saved model runs.

Column names are whitespace-trimmed in memory. Duplicate names created by trimming are rejected. Notebook input features follow `model_version` (1–4) from `ML/feature_versions.py`, using 4, 8, 21, or 23 columns in the declared order. Python calls without a version infer all CSV features except ID and label. The seven possible categorical column names default in `config.py`; only those selected by the input version are encoded and are applied by `load_basic_config()`. Split assignments come from a separate CSV. Clinical features must have no missing values; no imputation is performed. Scaling and one-hot encoding for XGBoost and Random Forest are fit on train only. CatBoost receives the declared categorical columns as string categories.
