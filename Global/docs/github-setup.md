## 자동 검사

`scope`가 PR 전체 변경으로 검사 범위를 결정하면 파일 정책·품질 검사(`checks`), Linux 테스트, 필요한 운영체제·Docker 검사가 병렬로 시작한다. 파일 정책은 범위와 관계없이 브랜치 규칙·코드 형식·충돌 표시·대용량 파일·비밀키·노트북 출력·데이터와 모델 파일을 점검한다. 개인 모델을 학습하거나 실제 환자 데이터를 내려받지는 않는다.

| 변경 범위 | Linux 테스트 | 추가 검사 |
|---|---|---|
| 문서·검토용 보고서만 | 생략 | 없음 |
| 개인 실험·노트북만 | 개인 실험 계약 검사 | 없음 |
| 테스트만 | 변경 테스트와 이를 가져다 쓰는 테스트 | 관련 Docker·운영체제 검사 |
| `pyproject.toml`의 명령 등록만 | 실제 설치된 명령·CLI 실행 검사 | Docker 명령·새 Jupyter 터미널 + Windows·macOS 명령 실행 |
| 공통 데이터 준비·특징·평가 코드 | 전체 | 없음 |
| MLflow 전송·실패 안내 | 전체 | Docker 전송 복구·공용 MLflow |
| 원격 비교 | 전체 | Docker 공용 MLflow |
| 컨테이너 시작·작업 환경 | 전체 | 환경 점검 + Docker 학습 환경·전송 복구 |
| MLflow 서버 | 전체 | 환경 점검 + Docker 전송 복구·공용 MLflow |
| 환경 점검 코드·공용 환경 확인 노트북 | 전체 | 환경 점검 |
| 결과 저장·재현 정보 등 공통 연결부 | 전체 | Docker 3종, 환경·경로 관련 변경은 운영체제 검사 |
| Python·패키지·빌드·CI 설정, 분류할 수 없는 변경 | 전체 | 전체 검사 |
| `main` 대상 PR, `main` 반영, 수동 실행 | 전체 | 전체 검사 |

여러 범위가 섞이면 필요한 검사를 합친다. 마지막 커밋의 파일만 보고 앞선 변경의 검사를 생략하지 않는다. 명령 등록은 TOML의 다른 설정이 동일할 때만 별도로 분류한다. 테스트 삭제·공유 설정 변경·분류 실패는 전체 검사로 확대한다.

Windows·macOS에서는 개인 환경·파일 잠금·경로처럼 운영체제에 영향을 받는 관련 테스트를 실행한다. 전체 검사에서는 두 운영체제의 전체 회귀와 환경 점검도 실행한다. 환경 점검은 합성 데이터·파형 예제와 `Global/notebooks/00_environment_check.ipynb` 실행이다.

전체 회귀는 운영체제별로 네 작업에 나눠 병렬 실행한다. 각 테스트는 한 작업에만 배정하고, 모든 작업이 성공해야 통과한다. 환경 점검·노트북 실행은 운영체제별 한 번만 수행한다. 범위를 좁힌 검사는 분할하지 않는다.

Docker 검사는 관련 기능에 따라 각각 선택하고 병렬 실행한다.

| 작업 | 확인할 내용 |
|---|---|
| 명령 실행 | 현재 CPU 이미지의 명령 등록·실행 + 새 Jupyter 터미널의 `dev`·Python 실행 |
| 학습 환경 | CPU 이미지 빌드·Compose 시작·Jupyter·개인 학습·결과 비교·재시작 후 파일 유지 |
| 전송 복구 | 연결 실패 후 로컬 보존·자동 재전송 |
| 공용 MLflow | 인증·팀원별 학습 결과 수집·원격 비교 |

학습 환경 검사는 시작·학습, 개인 노트북, 개인 패키지 환경·복원을 독립된 세 작업으로 나눈다. 명령 실행 검사는 학습 환경 검사에도 포함되므로 둘이 함께 선택되면 중복 실행하지 않는다.

Docker 이미지는 빌드 입력이 같은 레이어를 GitHub Actions 캐시에서 재사용한다. 학습 환경·MLflow 및 병렬 작업별 캐시를 구분하며, 테스트는 이번 실행에서 빌드한 이미지 ID와 입력 일치 여부를 확인한다. 캐시가 없어도 이미지를 새로 빌드하고 같은 검사를 수행한다. PR 캐시는 같은 PR의 후속 실행에서 재사용하며, 다른 PR에서 같은 캐시를 사용할 수 있다고 보장하지 않는다. GPU 이미지는 CI에서 빌드하거나 실행하지 않는다.

### 실행 시점과 병합

- PR 생성·재개·새 커밋·대상 브랜치 변경 시 검사한다. 제목·본문만 수정하면 검사하지 않는다.
- 같은 PR에 새 커밋을 올리면 이전 검사를 취소하고 최신 변경을 검사한다. 제목·본문 수정은 진행 중인 검사를 취소하지 않는다.
- PR에서 병합 결과를 미리 검사하므로 `develop` 병합 후에는 같은 검사를 반복하지 않는다. **병합 직전에 최신 `develop`을 반영하고 새 커밋의 검사 결과를 확인한다.**
- 제출 브랜치 `main`은 PR과 병합 후 모두 전체 검사한다. 필요하면 GitHub **Actions → Team checks → Run workflow**에서 브랜치를 선택해 전체 검사를 실행한다.

**선택된 검사가 모두 성공해야 마지막 `validate`가 통과한다.** 선택된 작업이 실패하거나 취소·생략되면 병합 조건을 충족하지 못한다. 검사 대상이 아니어서 생략한 작업은 정상이다. 문서 PR은 `scope`·`checks`·`validate`만 실행한다. 테스트가 필요한 PR에서는 선택된 Linux·운영체제·Docker 작업의 성공도 확인한다.

개인 실험의 데이터 사용·학습 방법은 [실험 리뷰](../../CONTRIBUTING.md#3-pr-만들기와-병합)로 확인한다. CI는 WSL2·NVIDIA 드라이버·실제 GPU 연산을 검증하지 않는다. 각 교육용 노트북에서 `docker compose up --build gpu`로 시작 시 GPU 점검을 통과하는지 확인한다. `./dev check --gpu`로 다시 점검할 수 있다.

로컬에서는 `./dev verify`로 같은 범위 기준을 적용한다. 커밋할 파일만은 `--staged`, 전체 검사는 `--full`을 사용한다. 정책 검사는 범위와 관계없이 유지하며 개인 학습 코드를 자동 실행하지 않는다.
