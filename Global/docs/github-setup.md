## 자동 검사

`scope`가 PR 전체 변경으로 검사 범위를 결정하면 파일 정책·품질 검사(`checks`), Linux 테스트, 필요한 운영체제·Docker 검사가 병렬로 시작한다. 파일 정책은 모든 PR에서 비밀키·환자 데이터·모델·노트북 출력·대용량 파일·코드 형식·충돌 표시를 점검한다. 개인 모델을 학습하거나 실제 환자 데이터를 내려받지는 않는다.

| 변경 범위 | Linux 테스트 | 추가 검사 |
|---|---|---|
| 문서·검토용 보고서만 | 생략 | 없음 |
| 개인 실험·노트북만 | 개인 실험 계약 검사 | 없음 |
| 테스트만 | 변경 테스트와 이를 가져다 쓰는 테스트 | 관련 Docker, 실행 환경 테스트가 바뀐 경우 해당 운영체제 검사 |
| 명령 등록만 | 설치된 명령·CLI 실행 | 실제 Docker·새 Jupyter 터미널 + 운영체제별 명령 실행 |
| 공통 데이터·정답·분할·평가 | 전체 | 없음 |
| 개인 환경·노트북 연결·학습 프로세스 실행 | 전체 | 관련 운영체제·Docker 검사, 보관 정보에 영향을 주면 복원 검사 |
| 저장·전송·보관·복원 | 전체 | 영향을 받는 실제 MLflow 연동·재시도 검사 |
| 컨테이너·서버 실행 환경 | 전체 | 환경 점검 + 관련 Docker 시나리오 |
| Python·공통 패키지 | 전체 | 전체 Docker + 명령 등록·기본 실행·노트북 커널의 운영체제별 최소 검사 |
| CI 설정, 분류할 수 없는 변경 | 전체 | 전체 Docker |
| `main` 대상 PR, 수동 전체 실행 | 전체 | 모든 OS·모든 Docker 시나리오 |

여러 범위가 섞이면 필요한 검사를 합친다. 마지막 커밋만 보고 앞선 변경의 검사를 생략하지 않는다. 명령 등록은 TOML의 다른 설정이 동일할 때만 별도로 분류한다. 테스트 삭제·공유 설정 변경·분류 실패는 보수적으로 검사 범위를 넓힌다.

`develop` PR의 Windows·macOS 검사는 명령 등록·개인 패키지 환경·노트북 커널·학습 프로세스 실행을 바꿀 때 관련 항목만 한 작업씩 실행한다. 데이터·평가·결과 저장·경로 설정이나 CI 설정·분류 불가 변경만으로 두 운영체제 검사를 확대하지 않는다. `./dev` 실행 도우미는 실제 Linux Docker로 검사한다. 모든 OS의 전체 회귀는 `main` 대상 PR과 수동 전체 검사에서 네 작업씩 나눠 실행한다. 선택된 모든 작업이 성공해야 한다.

Docker 검사는 시작·명령, 학습·저장·비교, 재시작·의존성 갱신, 개인 노트북, 개인 환경·복원, 결과 전송 재시도, 선택 모델 보관 재시도, 공용 MLflow로 구분한다. 각 시나리오는 독립적으로 실행한다. 실제 이미지의 설치·권한·Jupyter·인증·파일 보존·자동 전송기 동작을 확인하며, 변경과 관련된 시나리오만 선택한다.

Docker 이미지는 기존 PR 캐시와 `develop`의 공통 의존성 캐시를 읽는다. 공통 캐시는 `develop`에서 Docker 빌드 입력이 바뀔 때 별도로 갱신하며 PR 검사 완료를 지연시키지 않는다. 캐시가 없으면 새로 빌드하고 같은 검사를 수행한다. 이번 코드로 빌드한 이미지 ID와 입력 정보의 일치 여부도 확인한다. GPU 이미지는 CI에서 빌드하거나 실행하지 않는다.

### 실행 시점과 병합

- PR 생성·재개·새 커밋·대상 브랜치 변경 시 검사한다. 제목·본문만 수정하면 검사하지 않는다.
- 같은 PR에 새 커밋을 올리면 이전 검사를 취소하고 최신 변경을 검사한다. 제목·본문 수정은 진행 중인 검사를 취소하지 않는다.
- **병합 직전에 최신 대상 브랜치(`develop` 또는 `main`)를 반영하고, 해당 병합 결과의 `validate` 성공을 확인한다.** 대상 브랜치가 바뀌면 다시 반영하고 검사한다.
- `main` 대상 PR은 병합 전에 모든 OS·Docker 전체 검사를 실행한다. `main`·`develop` 병합 후에는 같은 검사를 반복하지 않는다. Docker 빌드 입력이 바뀌면 `develop`의 공통 캐시만 별도로 갱신한다.
- 필요하면 GitHub **Actions → Team checks → Run workflow**에서 브랜치를 선택해 전체 검사를 실행한다.

**선택된 검사가 모두 성공해야 마지막 `validate`가 통과한다.** 선택된 작업이 실패하거나 취소·생략되면 병합 조건을 충족하지 못한다. 검사 대상이 아니어서 생략한 작업은 정상이다. 문서 PR은 `scope`·`checks`·`validate`만 실행한다. 테스트가 필요한 PR에서는 선택된 Linux·운영체제·Docker 작업의 성공도 확인한다.

개인 실험의 데이터 사용·학습 방법은 [실험 리뷰](../../CONTRIBUTING.md#3-pr-만들기와-병합)로 확인한다. CI는 WSL2·NVIDIA 드라이버·실제 GPU 연산을 검증하지 않는다. 각 교육용 노트북에서 `docker compose up --build gpu`로 시작 시 GPU 점검을 통과하는지 확인한다. `./dev check --gpu`로 다시 점검할 수 있다.

로컬에서는 `./dev verify`로 같은 범위 기준을 적용한다. 커밋할 파일만은 `--staged`, 전체 검사는 `--full`을 사용한다. 정책 검사는 범위와 관계없이 유지하며 개인 학습 코드를 자동 실행하지 않는다.
