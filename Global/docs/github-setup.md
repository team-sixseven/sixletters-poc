## 자동 검사

`checks`는 브랜치 규칙·코드 형식·충돌 표시·대용량 파일·비밀키·노트북 출력·데이터와 모델 파일을 점검한다. 개인 실험·노트북만 바뀌면 데이터·분할·저장·환경 계약에 필요한 테스트를, 공통 코드·패키지가 바뀌면 전체 회귀 테스트를 같은 Linux 작업에서 실행한다. 개인 모델을 학습하거나 실제 환자 데이터를 내려받지는 않는다.

| 변경 범위 | Linux 공통 테스트 | 추가 검사 |
|---|---|---|
| 문서·검토용 보고서만 변경 | 생략 | 없음 |
| 개인 실험·노트북만 변경 | 개인 실험 계약 검사 | 없음 |
| 공통 데이터 준비·특징·평가 코드 | 전체 | 없음 |
| MLflow 전송 클라이언트·전송 실패 안내 | 실행 | Docker 전송 복구·공용 MLflow |
| 원격 비교 코드 | 실행 | Docker 공용 MLflow |
| 컨테이너 시작·작업 환경 | 실행 | 환경 점검 + Docker 학습 환경·전송 복구 |
| MLflow 서버 | 실행 | 환경 점검 + Docker 전송 복구·공용 MLflow |
| 환경 점검 코드·공용 환경 확인 노트북 | 실행 | 환경 점검 |
| 결과 저장·재현 정보 등 공통 연결부 | 실행 | Docker 3종 |
| Python·패키지·CI 설정, 분류하지 못한 파일 | 실행 | 전체 검사 |
| `main` 대상 PR, `main` 반영, 수동 실행 | 실행 | 전체 검사 |

여러 범위가 섞이면 필요한 검사를 모두 실행한다. 환경 점검은 합성 데이터·파형 예제와 `Global/notebooks/00_environment_check.ipynb` 실행이다. Windows·macOS의 직접 Python 실행 검사는 Python·패키지 변경을 포함한 전체 검사에서만 추가한다. 컨테이너 설정만 바뀌면 Linux에서 검사한다. 변경 파일 목록을 확인하지 못해도 전체 검사를 실행한다.

Docker 검사는 관련 기능에 따라 각각 선택하고 병렬 실행한다.

| 작업 | 확인할 내용 |
|---|---|
| 학습 환경 | CPU 이미지 빌드·Compose 시작·Jupyter·개인 학습·결과 비교·재시작 후 파일 유지 |
| 전송 복구 | 연결 실패 후 로컬 보존·자동 재전송 |
| 공용 MLflow | 인증·팀원별 학습 결과 수집·원격 비교 |

### 실행 시점과 병합

- PR 생성·재개·새 커밋·대상 브랜치 변경 시 검사한다. 제목·본문만 수정하면 검사하지 않는다.
- 같은 PR에 새 커밋을 올리면 이전 검사를 취소하고 최신 변경을 검사한다. 제목·본문 수정은 진행 중인 검사를 취소하지 않는다.
- PR에서 병합 결과를 미리 검사하므로 `develop` 병합 후에는 같은 검사를 반복하지 않는다. **병합 직전에 최신 `develop`을 반영하고 새 커밋의 검사 결과를 확인한다.**
- 제출 브랜치 `main`은 PR과 병합 후 모두 전체 검사한다. 필요하면 GitHub **Actions → Team checks → Run workflow**에서 브랜치를 선택해 전체 검사를 실행한다.

**선택된 검사가 모두 성공해야 마지막 `validate`가 통과한다.** 선택된 작업이 실패하거나 취소·생략되면 병합 조건을 충족하지 못한다. 검사 대상이 아니어서 생략한 작업은 정상이다. 추가 검사가 없는 코드·문서 PR은 `checks`와 `validate` 두 작업으로 끝나며, 문서 PR에서는 테스트 실행 단계도 생략한다.

개인 실험의 데이터 사용·학습 방법은 [실험 리뷰](../../CONTRIBUTING.md#3-pr-만들기와-병합)로 확인한다. CI는 WSL2·NVIDIA 드라이버·실제 GPU 연산을 검증하지 않는다. 각 교육용 노트북에서 `docker compose up --build gpu`로 시작 시 GPU 점검을 통과하는지 확인한다. `./poc check --gpu`로 다시 점검할 수 있다.

로컬에서는 `./poc verify`로 같은 범위 기준을 적용한다. 커밋할 파일만은 `--staged`, 전체 검사는 `--full`을 사용한다. 정책 검사는 범위와 관계없이 유지하며 개인 학습 코드를 자동 실행하지 않는다.
