# 공동 준비와 개인 실험

```text
공통 데이터·정답·환자 분할 확정
          ↓
각자 실험 폴더에서 전처리·학습·예측
          ↓
Experiment.save()로 공통 평가·결과 저장
          ↓
같은 조건의 검증 결과 비교 → 개선 반복 → 후보·임계값 고정
          ↓
저장된 모델로 최종 테스트 → 집계표·그래프
```

첫 실행 명령은 [README](../../README.md)를 따른다. 아래 명령은 Docker 작업 환경을 켜 둔 상태에서 **별도 Ubuntu 터미널의 저장소 최상위 폴더**에서 실행한다. Jupyter·컨테이너 터미널에서는 `./poc` 대신 `poc`을 쓴다.

## 1. 팀이 함께 준비할 것

| 공통 항목 | 확정할 내용 |
|---|---|
| 예측 목표 | 정답 정의·예측 시점·사용할 수 없는 사후 정보 |
| 데이터 | 원본 버전·변수 의미·오류와 단위·환자 포함/제외 기준 |
| 환자 분할 | 학습·검증·테스트 환자를 고정하여 공동 사용 |
| 입력 자료 | 임상 / ECG 구분과 환자 ID로 연결한 공통 환자 집합 |
| 평가·환경 | 같은 점수 계산·결과 형식·공통 패키지 버전, 추가 장비 조건 |
| 기준 결과 | 로지스틱 회귀와 랜덤 포레스트 또는 gradient boosting |

MUSIC은 같은 버전의 코드를 받고 `./poc music`으로 각자 준비한다. 정답·대상 환자·컬럼·분할은 [데이터 준비 기준](../data/README.md)에 고정되어 있다. 기준을 바꾸면 새 버전을 만들고 비교할 실험을 다시 실행한다. 개인적으로 환자를 제외하거나 분할 파일을 고치지 않는다.

**공동 데이터 정리와 개인 전처리는 구분한다.** 잘못된 코드값·단위 수정과 환자 분할은 공동 준비다. 결측치 대치·변수 선택·값 변환은 개인 실험이며, 계산에 필요한 값은 학습 데이터에서만 구한다.

## 2. 각자 자유롭게 실험할 것

| 개인이 바꿀 부분 | 예시 |
|---|---|
| 모델·학습 코드 | scikit-learn 모델, 직접 작성한 신경망, 학습 파일명·보조 코드 구성 |
| 개인 패키지·설정 | 이름별 추가 라이브러리, 필요할 때 실험별 환경 분리, YAML·JSON 등 학습 설정 |
| 전처리·변수 | 결측치 처리, 값 변환, 허용된 변수 선택·특징 계산 |
| 학습 설정 | 설정 탐색, 난수 시드, 반복 학습·조기 종료 |
| 불균형 대응 | 드문 사건의 가중치 조정, 학습 데이터 안의 표본 구성 변경 |
| 모델 조합·저장 | 여러 예측 조합, 장비별 실행, 모델 형식 선택 |

같은 모델을 여러 명이 실험해도 되고 한 사람이 여러 모델을 실험해도 된다. 특정 공통 학습 함수를 사용할 의무는 없다.

공통 정답·환자 분할·평가 계산은 유지한다. 교차 검증·조기 종료의 내부 분할도 **학습 환자 안에서만** 만든다. 검증·테스트 환자를 전처리 계산이나 학습에 사용하지 않고 사후 정보를 입력에 추가하지 않는다. 새로운 원본 변수가 필요하면 공동 준비 단계에서 검토한다.

## 3. 개인 실험 만들기

`./poc init`에 등록한 이름으로 생성한다. 별도로 유지할 방법은 `exp002`처럼 새 폴더를 만든다.

```sh
./poc new exp001 --feature-set clinical
```

```text
Members/이름/experiments/exp001/
├── train.py          학습 시작 파일: 이름 변경 가능
├── predict.py        저장한 모델의 최종 예측 예제
├── preprocessing.py  필요한 보조 코드: 직접 추가
├── config.toml       이름·실험명·입력 변수·학습 설정
├── configs/          추가 설정: 직접 추가
└── outputs/          내보낸 모델·생성 파일: Git 제외
```

기본 예제는 로지스틱 회귀다. `--model random-forest`를 붙이면 랜덤 포레스트로 만든다. 둘 다 학습 데이터에서 결측치 처리·범주형 인코딩·클래스 가중치를 계산하고, `Experiment.save()`로 결과를 저장한다. 로지스틱 회귀에는 표준화도 포함한다. `train.py`는 자유롭게 바꾸고 보조 파일을 추가한다. 예를 들어 `./poc new exp002 --model random-forest --script fit_rf.py`로 생성한다.

추가 패키지가 없는 새 실험은 공통 환경으로 실행하며 개인 `.venv/`를 만들지 않는다. `./poc env add`로 패키지를 추가하면 `Members/이름/`의 환경을 만들어 같은 이름의 실험들이 공유한다. 기존에 고정한 환경은 유지하며, 필요한 실험만 `./poc env isolate exp002`로 분리한다. [개인 작업 공간 구조](../../Members/README.md)

임상·ECG·결합 각각의 로지스틱 회귀와 랜덤 포레스트를 만들려면 `./poc baselines`를 쓴다. **학습은 자동으로 시작하지 않는다.** 생성된 개인 코드로 각자 실행한다. [6개 기준 모델 실행](final-evaluation.md#1-기준-모델-준비)

| 설정 항목 | 의미 |
|---|---|
| `[experiment].owner`, `name` | 이름별 폴더의 이름과 실험명 |
| `feature_set` | `clinical`(임상), `ecg`(심전도), `combined`(결합) |
| `seed` | 실제 코드에 적용할 난수 시드. 사용하지 않으면 생략 |
| `features` | 해당 입력 그룹에서 사용할 열 목록. 생략하면 전체 |
| `[parameters]` | 실제 코드에 적용할 학습 설정 |

모델은 개인 학습 코드에서 선택한다. 기본 예제는 `seed`·`parameters`를 읽어 모델에 적용하고, 학습한 모델 객체에서 이름·실제 설정을 읽어 저장한다. 학습 코드를 바꾸면 새 모델에 맞게 설정을 읽고 적용하는 부분도 수정한다. `features`는 선택한 입력 그룹의 허용된 열만 지정한다. ECG 추가 효과를 비교할 때는 각 그룹 전체를 사용한다.

기존 실험을 바탕으로 시작하려면 `./poc new exp002 --from exp001`을 사용한다. 작성자·실험명은 새 값으로 바꾸고 Python 코드·설정·출력을 지운 노트북·설명은 복제한다. 모델·데이터·결과·가상환경은 복사하지 않는다. 원본이 이름별 환경을 쓰면 그대로 공유하고, 분리 환경이면 고정 패키지 기록을 복사해 새 분리 환경을 준비한다. 복제 후 실행할 Python 파일과 설정은 직접 확인한다.

## 4. 학습하고 결과 확인하기

```sh
./poc exec exp001 train.py
```

`train.py`를 `fit_rf.py`로 바꿨다면 `./poc exec exp001 fit_rf.py`로 실행한다. 보조 코드는 실험 폴더와 하위 폴더에 추가하고 학습 코드에서 불러온다. 추가 패키지는 `./poc env add exp001 패키지이름`으로 현재 연결된 환경에 설치한다. 기본은 같은 이름의 실험들에 함께 적용되며, 분리한 실험은 그 실험에만 적용된다. [패키지 추가·환경 분리](development.md#5-패키지-추가변경)

기본 데이터 경로는 `./poc init`에서 정한다. 한 번만 다른 데이터로 실행하려면 `--data Global/data/prepared/music-scd-hrv-v1`처럼 지정하며, 해당 데이터를 먼저 준비한다. GPU 사용은 [개발 환경](development.md#2-nvidia-gpu-사용)을 따른다.

개인 학습 파일이 전처리·학습·모델 내보내기를 직접 수행한다. `./poc exec`는 실험에 맞는 공통 또는 개인 환경을 선택하고 실행 파일명·인자를 기록한다. 이 기록은 `Experiment.save()` 결과에 포함된다. 패키지 고정 파일이 있으면 실제 Python 버전·패키지와 일치하는지도 확인한다. 학습 파일을 `python`으로 직접 실행하면 이 실행 정보가 자동 기록되지 않으므로, 공유할 결과는 `./poc exec`로 실행한다. `from sixletters.experiment import Experiment`의 공통 객체는 데이터 검사·평가·기록만 담당한다.

| API | 역할 |
|---|---|
| `Experiment(data=..., config=...)` | 준비 데이터·설정 검사. **학습 전에 생성** |
| `training_data()` | 학습 입력 `X`와 정답 `y` 반환 |
| `validation_data()` | 정답이 없는 검증 입력 반환 |
| `settings`, `parameters`, `categorical_features` | 설정·학습 설정·범주형 열 확인 |
| `save(predictions, model_files=..., training=...)` | 학습 정보·예측을 검사하고 모델 파일과 함께 로컬 저장. 서버 통신 없이 반환 |

공통 설정 파일은 개인 실험 폴더에 둔다. 생성된 예제의 `--config`도 이 폴더 안의 설정만 허용한다. 결과는 코드 폴더 밖에 저장하며 기본 경로는 `Global/artifacts/`다. 예제의 `--output-root`로 다른 저장 경로를 지정할 수 있다.

학습·검증 입력의 행 인덱스는 `patient_id`다. 예측 후에도 ID와 값을 정확히 연결하고, `save()`에는 다음 **두 열만** 전달한다.

| 열 | 조건 |
|---|---|
| `patient_id` | 공통 검증 환자마다 한 행. 누락·중복·추가 환자 없음 |
| `score` | 정답이 `1`일 예측 확률. 0~1의 유한한 숫자 |

공통 평가가 ID로 정답을 연결해 점수를 계산한다. 개인 코드에서 정답이나 계산한 점수를 제출하지 않는다. `model_files`에는 개인 코드가 `outputs/` 또는 임시 폴더에 내보낸 모델 파일을 **하나 이상** 전달한다. 형식·파일 수는 자유롭다. [모델 출력과 추가 설정 보관](../artifacts/README.md)

직접 작성한 학습 코드에서도 `Experiment.save()`를 호출해야 로컬 결과와 전송 대상이 만들어진다. 저장할 때 실제 모델의 이름·난수 시드·설정을 전달한다. 모델 객체가 있으면 이름을 문자열로 따로 적지 않고 해당 객체에서 읽는다. 설정 탐색을 했다면 최종 선택한 모델의 값을 사용한다.

```python
experiment.save(
    predictions,
    model_files={"model.pkl": exported_model_path},
    training={
        "model": type(trained_model).__name__,
        "seed": actual_seed,
        "parameters": actual_parameters,
    },
)
```

`trained_model`은 실제 학습한 모델 객체이며, 파이프라인을 사용한다면 마지막 분류기를 지정한다. `actual_seed`는 정수 또는 `None`, `actual_parameters`는 실제 설정을 담은 사전이다. scikit-learn 모델은 `get_params(deep=False)`로 설정을 읽을 수 있다. 설정값은 문자열·숫자·불리언·리스트·사전 등 JSON으로 저장할 수 있는 값이며 모델 객체·함수는 넣지 않는다.

XGBoost의 `missing=NaN`처럼 특수한 숫자와 NumPy 스칼라는 `save()`가 저장용 표현으로 자동 변환한다. 모델에 전달한 설정은 바꾸지 않는다. 예를 들어 `NaN`은 `{"__sixletters_float__": "nan"}`으로 기록하며, 일반 문자열 `"NaN"`과 구분한다. 이 예약 키를 설정 사전에 직접 사용하지 않는다. 배열·모델 객체·함수 등 지원하지 않는 값은 해당 설정 경로를 표시하고 거절하므로, 배열은 리스트로 바꾸고 객체·함수는 이름과 필요한 설정만 기록한다. `config.toml`의 설정과 예측 확률에는 기존의 유한한 숫자 조건이 유지된다.

**기록 단위는 `save()` 호출이다.** 여러 설정의 결과를 비교하려면 저장할 결과마다 실제 설정·모델·예측을 전달한다. 학습 함수 호출 자체를 추적하지는 않는다. 전체 파일은 `Global/artifacts/이름/실험명/실행ID/`에 보관되고 기존 실행을 덮어쓰지 않는다. `save()`는 서버 응답을 기다리지 않으며, 연결된 Docker 작업 환경이 기본 60초 간격으로 미전송 결과를 처리한다. 저장 파일은 [실행 결과](../artifacts/README.md), 자동 전송 대상·수동 전송은 [팀 결과 수집](tracking.md)을 따른다.

학습 중 해당 실험의 코드·설정·공통 데이터 또는 학습·평가 관련 공통 코드가 바뀌면 저장이 중단된다. 공통 명령 화면·전송·개인 설정·실험 생성·개인 환경 관리 코드만 바뀐 경우는 저장을 막지 않는다. **실제 학습 패키지나 사용 중인 환경의 패키지 고정 파일 변경은 여기에 해당하지 않는다.** 실행 당시 개인·공통 Python 코드와 추가 설정, 사용한 패키지 파일 사본을 보관한다. 개인 코드의 `.venv/`·캐시는 제외한다. 추가 설정·패키지 고정 파일의 보관 범위와 제한은 [실행 결과](../artifacts/README.md#추가-설정-보관)를 따른다. 동시에 다른 학습 방법을 작성하려면 별도 실험 폴더를 사용한다.

새 공통 Python 모듈은 기본적으로 학습·평가 관련 변경에 포함한다. 공통 기능이 임의 코드의 데이터 사용까지 차단하지는 않으므로 정보 유출·실제 설정 일치는 리뷰로 확인한다.

실행만 점검할 때는 `./poc demo` 후 `./poc init`에서 `Global/data/prepared/demo-v1`을 등록한다. 합성 데이터 점수는 실제 환자 데이터의 성능이 아니다.

## 5. 두 가지 비교를 구분하기

| 모드 | 확인할 질문 | 같아야 하는 조건 | 달라도 되는 조건 |
|---|---|---|---|
| `experiments` | 어떤 개인 방법이 더 좋은가? | 데이터·환자·정답·분할·입력 그룹·평가 기준 | 모델·전처리·선택 변수·학습 설정·시드 |
| `inputs` | ECG 추가가 도움이 되는가? | 데이터·환자·정답·분할·모델·전처리·학습 설정·시드·평가 기준·환경 | 임상 / ECG / 결합 입력 그룹 |

개인 방법 비교는 같은 입력 그룹의 실행을 **2개 이상** 선택한다. 공용 서버 없이 로컬 결과를 비교할 때는 `--remote`를 뺀다.

```sh
./poc compare --remote
```

목록은 **검증 환자 수·SCD 수·AUROC·AP·Brier 점수와 95% 신뢰구간**, 시각을 보여준다. MUSIC SCD 과제 이외의 데이터는 SCD 대신 **양성(`target=1`) 수**를 표시한다. 같은 설정은 한 번 표시하고, 모델·시드·학습 설정이 다른 부분은 실행별로 표시한다. 값이 없는 설정과 명시적인 `null`은 구분하며, 원격에 완전한 설정이 없으면 확인 불가로 표시한다. 이전 로컬 결과에 저장 시각이 없으면 파일 수정 시각을 대신 표시한다.

목록은 **최근 20개**가 기본이다. 다음 옵션은 로컬·원격 목록과 `./poc archive`의 로컬 선택 목록에서 사용할 수 있다. 필터 값은 표시된 이름과 정확히 일치해야 하며, 조건에 맞는 실행을 찾은 뒤 최신순으로 개수를 제한한다.

| 옵션 | 뜻 |
|---|---|
| `--owner "본인이름"` | 해당 작성자의 실행 |
| `--dataset music-1.0.1-scd-basic-v1` | 해당 데이터 ID의 실행. 준비 폴더 이름과 다를 수 있음 |
| `--feature-set clinical` | `clinical` / `ecg` / `combined` 입력 그룹 |
| `--limit 50` | 최근 실행 최대 50개. 1 이상의 정수 |

```sh
./poc compare --remote --dataset music-1.0.1-scd-basic-v1 --feature-set clinical --limit 50
./poc compare --owner "본인이름" --feature-set clinical
```

같은 실행을 다시 비교하려면 원격 목록에 표시된 **MLflow ID** 두 개 이상을 `./poc compare --remote --run-ids ID1 ID2`로 지정한다. `ID1`, `ID2`는 실제 ID로 바꾼다. 로컬은 `--runs "실행 폴더 1" "실행 폴더 2"`를 사용한다. 직접 지정할 때는 목록 필터·`--limit`를 함께 쓰지 않는다. `--root`는 로컬 목록의 검색 위치 또는 원격 결과 캐시의 저장 위치를 바꾼다. 로컬 `--runs`에는 `--root`를 함께 쓰지 않는다. 직접 선택해도 비교 조건 검증은 동일하다.

**처음 선택한 실행을 기준**으로 나머지 실행의 점수 차이를 계산한다. 다른 기준을 쓰려면 `--reference 실행ID`를 붙인다. 여기에는 MLflow ID가 아닌 목록의 `이름/실험명/실행ID`에서 마지막 **저장된 실행 ID**를 넣고, 그 실행도 비교 대상으로 선택한다.

팀원별 방법 비교는 같은 데이터·입력 그룹에서 이름별로 실행 하나씩 선택한다. 목록의 점수는 선택용이며 자동으로 최적 모델을 정하지 않는다. 원격 목록에서 선택한 실행만 내려받아 검증하며, 모델 보관 완료를 기다릴 필요는 없다. 환자별 예측으로 점수를 다시 계산하고 데이터·정답·분할을 확인한다. 기본 MUSIC과 HRV 분석은 대상 환자가 달라 함께 비교하지 않는다.

ECG 추가 효과는 **같은 코드와 학습 설정에서 `feature_set`만 바꾸어** 임상·ECG·결합 실험을 실행한 뒤 비교한다. 일부 열을 고르는 `features`는 사용하지 않고, 실제 코드에서도 전체 입력을 사용했는지 리뷰한다.

입력 그룹 비교는 개인 학습 코드·추가 설정·학습 및 평가 관련 공통 코드·설정·환경을 확인한다. 명령 화면·전송·개인 환경 관리 등 보조 코드만 달라진 새 결과는 함께 비교할 수 있다. 이전 결과도 읽기·전송·비교할 수 있다. 다만 **공통 코드를 검사하는 범위가 다른 버전끼리** 입력 그룹을 비교하거나 변경 구분 정보가 없는 결과가 섞이면 전체 공통 코드의 일치를 확인한다. 이 조건으로 비교가 거절되면 같은 버전에서 필요한 실험을 다시 실행한다.

```sh
./poc compare --remote --mode inputs
```

조건이 다르면 기준·대상 실행, 서로 다른 항목·값, 필요한 조치가 표시된다. 예를 들어 환경 차이는 패키지 이름과 버전을, 코드 차이는 코드 식별 값을 보여준다. 환자 목록·민감한 설정값은 표시하지 않는다. 잘못 선택한 실행을 바꾸거나 안내된 조건을 맞춰 다시 실행하며, 저장된 결과 파일을 수정해서 통과시키지 않는다.

비교표는 `Global/artifacts/comparisons/`에 생기며 덮어쓰지 않는다. 파일명을 정하려면 `--output Global/artifacts/comparisons/clinical-v1.csv`를 붙인다.

| 지표 | 의미 | 좋은 방향 |
|---|---|---|
| `roc_auc` (AUROC) | 정답 1과 0의 순위를 구분하는 정도 | 높을수록 |
| `average_precision` (AP) | 정밀도·재현율 곡선 기반 요약 점수 | 높을수록 |
| `brier_score` | 예측 확률과 정답의 제곱 오차 | 낮을수록 |

AP를 다른 방식으로 계산한 PR 곡선 면적과 같은 값으로 간주하지 않는다.

신뢰구간은 **저장된 검증 예측**에서 양성·음성 환자 수를 유지하며 각 집단의 환자를 중복 추출해 2,000번 점수를 다시 계산한 범위다(층화 bootstrap, seed 42, 2.5~97.5백분위). 모델을 재학습하거나 테스트 데이터를 사용하지 않는다. 재학습·후보 선택의 불확실성까지 포함하지 않으며, 구간의 겹침만으로 모델 간 우열을 판단하지 않는다. 어느 한 집단이 2명 미만이면 환자 수·점수는 표시하고 신뢰구간은 계산 불가 사유를 표시한다.

**차이 신뢰구간**은 환자 ID·정답을 맞춘 뒤, 매번 같은 환자 표본을 두 실행에 적용해 `대상−기준`을 계산한다(짝지은 bootstrap). AUROC·AP 차이는 양수, Brier 차이는 음수일수록 개선이다. 구간이 0을 포함하면 개선됐다고 단정하지 않는다. 이 비교는 탐색용이며 여러 후보를 반복해서 고르는 과정까지 보정하지 않는다. 기준 실행 자체의 차이와 구간은 0이다.

비교 CSV에는 기존 점수·설정과 함께 다음 열이 추가된다.

| 열 | 의미 |
|---|---|
| `patient_count`, `positive_count`, `negative_count` | 검증 환자 전체 수, 정답 1의 수, 정답 0의 수 |
| `scd_count` | MUSIC SCD 과제의 정답 1 수. 다른 과제는 빈 값 |
| `지표명_ci_lower`, `지표명_ci_upper` | 해당 점수의 95% 신뢰구간 하한·상한 |
| `ci_level`, `ci_method`, `ci_repeats`, `ci_seed` | 신뢰수준·계산 방법·반복 횟수·시드 |
| `ci_unavailable_reason` | 신뢰구간을 계산하지 못한 사유 |
| `reference_run_id`, `reference_owner`, `reference_experiment`, `is_reference` | 기준 실행과 해당 행이 기준인지 여부 |
| `지표명_delta`, `지표명_delta_ci_lower`, `지표명_delta_ci_upper` | 대상−기준 점수 차이와 그 95% 신뢰구간 |
| `delta_ci_level`, `delta_ci_method`, `delta_ci_repeats`, `delta_ci_seed`, `delta_ci_unavailable_reason` | 차이 구간의 계산 정보·계산 불가 사유 |

## 6. 공유하고 제출 후보 선택하기

1. 검증 결과로 방법·설정을 개선하고 후보를 선택한다. 다른 전처리·모델을 조합하면 새 실험으로 평가한다.
2. 모델을 공유·재현할 실행은 전체 결과 폴더가 있는 컴퓨터에서 `./poc archive`로 선택하고 [보관 완료](tracking.md#선택한-실행의-모델-보관)를 확인한다. 서버 쓰기 권한이 있으면 작성자 외 팀원도 실행할 수 있지만, 원격 비교에서 받은 결과만으로는 모델을 전송할 수 없다.
3. 코드·설정·[검토한 집계 결과](../reports/README.md)를 PR로 `develop`에 반영한다. 공유·재현할 작업 단위로 PR을 만들며 매 실행마다 만들지 않는다.
4. 통합된 코드·같은 데이터·해당 환경에서 검증 결과를 확인한다. [최종 평가](final-evaluation.md)에 따라 후보·임계값을 고정하고 저장된 모델로 테스트를 예측한다. 검증 예측 재현 확인 후 최종 집계표·그래프를 만든다. 테스트 점수로 반복 개선하지 않는다.
5. 필수 비교·개선 결과·누락과 제외·오류 분석·한계를 보고서에 정리하고 `main` 릴리스 PR을 만든다.

기업 제출에는 **로지스틱 회귀와 랜덤 포레스트 또는 gradient boosting 비교**, **같은 환자·분할에서 임상 / ECG / 결합 비교**를 포함한다. 개인 개선 결과도 이 기준 결과와 함께 정리한다.

공통 기능은 검증 비교와 최종 테스트 평가를 분리한다. `final report`는 확정한 후보의 AUROC·AP·Brier·민감도·특이도·혼동행렬, bootstrap 95% 신뢰구간과 ROC·PR·보정 그래프를 생성한다. 사전 실습 그래프가 제출 후보의 최종 평가를 대신하지는 않는다. 데이터 처리 근거·오류 분석·결과 해석은 팀이 별도로 작성한다.

원시 ECG 특징 추출·학습도 별도 구현 대상이다. 개인 코드가 파형을 읽더라도 공통 환자 분할을 유지하고 환자별 예측을 제출한다. 추가 파일의 버전·처리 방법을 실험 설명에 기록한다. WFDB·NeuroKit2는 공통 이미지에 포함되며 NPU 환경은 별도로 준비한다.
