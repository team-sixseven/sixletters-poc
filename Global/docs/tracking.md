# 팀 결과 수집

팀 공용 MLflow 서버에 연결하면 각자 개인 학습 파일로 만든 결과를 한곳에서 조회·비교할 수 있다. 서버 없이도 로컬 학습·저장·비교는 가능하다. 서버 설치와 계정·백업 관리는 [공용 서버 운영](tracking-server.md)을 따른다.

이 문서의 명령은 Docker 작업 환경을 켜 둔 상태에서, **별도 Ubuntu 터미널의 저장소 최상위 폴더**에서 실행한다. Jupyter·컨테이너 터미널을 사용하면 `./dev` 대신 `dev`로 실행한다.

| 시점 | 로컬 보관 | 서버 전송 |
|---|---|---|
| `Experiment.save()` | 모델·코드·설정·예측·점수 전체 | 저장 중에는 통신하지 않음. Docker 작업 환경이 기본 결과를 백그라운드 전송 |
| `./dev archive`로 실행 선택 | 기존 결과 유지 | 같은 실행에 모델·재현용 파일 추가 |

`./dev new`로 생성한 학습 예제에는 `Experiment.save()` 호출이 포함되어 있다. 직접 작성한 코드도 비교할 결과마다 이 함수를 호출해야 한다. 학습 함수를 호출하는 것만으로 기록되지는 않으며, 별도 MLflow 업로드 코드는 필요 없다. 저장이 끝나면 다음 실험을 시작할 수 있다. 원본·준비 데이터는 두 경우 모두 전송하지 않는다.

## 팀원 연결

저장소의 `.env`에 발급받은 실제 주소·계정을 입력한다. 파일이 없을 때만 `cp .env.example .env`로 만든다.

```dotenv
MLFLOW_TRACKING_URI=https://실제공용서버주소
MLFLOW_TRACKING_USERNAME=본인계정
MLFLOW_TRACKING_PASSWORD='본인비밀번호'
MLFLOW_EXPERIMENT_NAME=sixseven-poc
```

숨김 파일이 보이지 않으면 Ubuntu에서 `nano .env`로 연다. `Ctrl+O` → Enter로 저장하고 `Ctrl+X`로 닫는다. 전송 간격은 기본 60초이며 `POC_TRACKING_SYNC_INTERVAL`로 5~3600초 사이에서 바꿀 수 있다.

`.env`와 `.env.tracking`의 비밀번호는 작은따옴표로 감싸야 `$`가 변수로 치환되지 않는다. 비밀번호 자체의 작은따옴표는 `\'`로 적는다. 터미널의 비밀번호 입력 안내에는 따옴표를 덧붙이지 않는다. [Docker 환경 파일 문법](https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/#env-file-syntax)

예를 들어 서버가 `100.80.10.20:5000`에 열려 있다면 `http://100.80.10.20:5000`을 입력한다. 실제 서버 주소로 바꿔야 한다.

- `localhost`는 각자 자신의 컴퓨터이므로 공용 주소로 쓰지 않는다. 서버와 학습 컨테이너가 같은 컴퓨터여도 도달 가능한 서버 주소를 쓴다.
- `host.docker.internal`은 같은 컴퓨터의 호스트용이다. Linux에서 `127.0.0.1`에만 열린 서버에는 이 경로로 접속할 수 없다.
- `.env`·비밀번호·비밀키는 Git·노트북·PR에 올리지 않는다. 개인 실험만 할 때는 연결 항목을 비워 둔다.

설정을 저장한 뒤 [환경 시작·갱신](development.md#4-파일-보관과-환경-갱신)을 진행한다. 기존 환경이 켜져 있으면 학습을 마친 뒤 다시 시작해야 변경한 연결 정보가 적용된다.

## 팀 결과 조회와 비교

브라우저에서 공용 서버 주소를 열고 로그인한다. `sixseven-poc`에서 이름·실험명·입력 그룹·데이터 버전·점수를 확인한다. **`FINISHED` + `sixletters.complete=true`는 기본 결과 전송 완료**이며, 모델 보관 완료와는 다르다.

```sh
./dev compare --remote
```

완료된 실행 목록에서 비교할 결과를 **2개 이상** 선택한다. 기본으로 최근 20개를 표시한다. `--dataset`·`--feature-set`·`--owner`로 좁히거나 `--limit 50`으로 표시 개수를 늘릴 수 있다. 같은 데이터·입력 그룹에서 이름별로 실행 하나씩 고르면 팀원들의 방법을 비교할 수 있다. 모델 전송 여부와 관계없이 비교된다. [필터와 실행 ID 선택](parallel-work.md#5-두-가지-비교를-구분하기)

목록에는 검증 환자 수·SCD 수(다른 과제는 양성 수), 점수(AUROC·AP·Brier)와 95% 신뢰구간, 모델·seed, 공통 설정과 실행별 설정 차이가 표시된다. 새로 전송한 실행은 집계 정보를 함께 기록한다. 이전 원격 실행에 집계 정보가 없으면 `미기록`으로 표시하고, 선택해 비교할 때 예측 파일에서 계산한다. [신뢰구간 계산·해석](parallel-work.md#5-두-가지-비교를-구분하기)

원격 목록의 시각은 **서버 등록 시각**이다. 설정을 온전히 읽을 수 없는 실행은 `확인 불가`로 표시하며, 값이 없다는 뜻인 `null`이나 설정 자체가 없는 `미기록`과 구분한다.

같은 로컬 실행 ID가 서버에 여러 개 있으면 **해당 복사본 모두를 비교에서 제외**하고 `duplicate_remote`와 MLflow 실행 ID들을 표시한다. 정상 결과는 계속 조회·비교할 수 있다. 제외된 ID를 `--run-ids`로 직접 지정해도 비교하지 않는다. 중복 실행은 자동 삭제하지 않으며, 표시된 ID들을 기준으로 서버 관리자와 보관할 실행을 확인한다. 정상 결과가 2개 미만이면 비교할 수 없다.

선택한 결과의 점수 기록·환자별 예측·검증 정보만 `Global/artifacts/.remote/`에 내려받고, 비교표는 `Global/artifacts/comparisons/`에 만든다. 모델은 내려받지 않는다. 비교 명령은 검증한 환자별 예측으로 점수·환자 수·신뢰구간을 다시 계산하고 비교 조건을 검사한다. 화면에 나란히 보이는 점수만으로 같은 조건이라고 판단하지 않는다.

| 비교 | 명령 |
|---|---|
| 같은 입력 그룹에서 개인 방법 비교 | `./dev compare --remote` |
| 같은 학습 방법에서 임상 / ECG / 결합 비교 | `./dev compare --remote --mode inputs` |
| 로컬 결과 비교 | `./dev compare` |

데이터·환자·분할·학습 조건의 상세 기준은 [실험 비교](parallel-work.md#5-두-가지-비교를-구분하기)를 따른다. PR에는 MLflow 실행 링크와 [검토한 집계 결과](../reports/README.md)를 공유한다.

## 선택한 실행의 모델 보관

**실행할 컴퓨터에 해당 실행의 전체 원본 결과 폴더가 있고, 연결한 MLflow 계정에 해당 실험의 쓰기 권한이 있으면 팀원 누구나 실행할 수 있다.** 학습한 사람으로 제한하지 않는다. 원본 폴더는 `Global/artifacts/이름/실험명/실행ID/`이며, 모델 파일 하나만으로는 부족하다. 다른 팀원이 실행하려면 이 폴더 전체를 전달받아 **저장소 안의 같은 이름·실험명·실행 ID 구조**로 넣는다. 파일을 수정하지 않는다. 저장소 밖의 호스트 경로는 컨테이너에서 바로 읽을 수 없다.

`./dev compare --remote`로 받은 `Global/artifacts/.remote/`에는 모델·재현 파일이 없으므로 이 캐시로는 `archive`할 수 없다. 전체 결과를 보관한 컴퓨터에서 로컬 실행 **하나**를 선택한다. 다시 학습할 필요는 없다.

```sh
./dev archive
```

경로를 알고 있으면 직접 지정할 수 있다.

```sh
./dev archive --run "Global/artifacts/본인이름/exp001/실행ID"
```

같은 MLflow 실행의 `reproduction/`에 모델·개인 코드·공통 코드·추가 설정·패키지 고정 파일·기본 결과 파일 전체와 검증 정보를 추가한다. 파일별 설명은 [실행 결과](../artifacts/README.md)를 따른다. 모델 형식은 그대로 유지하며, 학습 데이터는 기록된 버전의 공통 준비 명령으로 별도 준비한다. 패키지 파일은 이름별 공유 여부와 관계없이 **해당 실행 당시의 사본**을 사용한다. 자동 보관 범위 밖의 파일·장비 조건과 모델 읽기 방법은 실험 설명에 기록한다. 추가 설정과 패키지 고정 파일은 모델 보관을 선택했을 때만 서버로 전송한다.

| `sixletters.archive_status` | 의미 |
|---|---|
| `none` | 선택하지 않음. 기본 결과만 전송 |
| `pending` | 전송 중이거나 재시도 필요 |
| `complete` | 보관 완료. `reproduction/`에서 다운로드 가능 |

`Model and reproduction files uploaded to the existing MLflow run.`이 표시되면 완료다. 연결 실패 시 선택 요청이 로컬에 남고 재시도로 이어진다. 서버에 도달하기 전에는 태그가 갱신되지 않을 수 있으며, 다시 선택해도 새 MLflow 실행을 만들지 않는다.

**추가 전송 완료 전에는 로컬 실행 폴더를 지우지 않는다.** 기본 결과만으로 모델을 복원할 수 없다. 로컬·서버 파일은 자동 삭제하지 않는다. 이전 방식으로 전체 파일을 올린 실행은 보관 태그가 없어도 기존 `bundle/`에 모델·코드가 남아 있다.

## 보관한 실험 복원

같은 버전의 공통 데이터를 준비한 뒤 **새 실험명**으로 복원한다. 다음 명령은 서버에서 모델 보관이 완료된 실행을 보여주며 번호 하나를 선택한다.

```sh
./dev restore retry001 --remote
```

`--source-owner 이름`·`--experiment exp001`·`--dataset 데이터ID`·`--feature-set clinical`·`--limit 50`으로 목록을 좁힌다. `--list`는 조회만 하고, `q`는 취소한다. `--remote`를 빼면 로컬 결과를 선택한다. 목록의 보관 상태는 원격이면 서버 정보, 로컬이면 마지막 전송 기록이며 서로 구분해 표시한다.

원본을 알고 있으면 경로나 서버 ID를 직접 지정할 수 있다.

```sh
./dev restore retry001 --run "Global/artifacts/작성자/실험명/실행ID"
```

```sh
./dev restore retry001 --run-id MLFLOW_ID
```

`MLFLOW_ID`는 MLflow 화면의 실행 ID다. 로컬 `result.json`의 `run_id`와 다르므로 혼용하지 않는다. 서버 읽기 권한과 `sixletters.archive_status=complete`가 필요하다. 기본 결과만 있는 실행은 먼저 전체 원본이 있는 컴퓨터에서 `archive`한다.

복원 위치는 `Members/본인이름/experiments/retry001/`이다. **복원한 실험은 이름별 추가 패키지를 상속하지 않도록 분리**한다. 보관된 개인 패키지 파일이 있으면 그 버전으로 환경을 준비한다. 없으면 현재 공통 환경을 사용하므로 원본 `result.json`의 Python·패키지 버전과 일치하는지 확인한다. 현재 이름별 환경은 바뀌지 않는다. `Verified original run:`에는 검증된 전체 원본 실행 경로가 표시된다. 최종 후보를 고정할 때는 이 경로를 `final freeze --runs`에 쓰거나, [원격 후보 선택](final-evaluation.md#2-최종-후보와-임계값-고정)을 사용한다.

| 복원 내용 | 위치 |
|---|---|
| 개인 Python 코드·추가 설정 | 원래 상대 경로 |
| 보관된 패키지 파일·환경 선택 | 분리를 지정한 `environment.toml`. 원본에 개인 패키지 파일이 있으면 함께 복원 |
| 실행 설정 | `config.toml` 및 원래 설정 파일명. 작성자·실험명만 새 이름으로 변경 |
| 원본 모델·공통 코드 사본 | `outputs/.restore/models/`, `outputs/.restore/shared_source/` |
| 원본 실행 ID·명령·환경·복원 경로 | `outputs/.restore/trace.json` |

파일의 크기·내용 식별 정보와 공통 데이터·정답·분할이 일치하는지 검사한다. 기존 실험을 덮어쓰거나 저장된 코드를 자동 실행하지 않는다. 원본의 `execution` 기록에서 파일명·인자를 확인하고, 현재 장비의 데이터 경로와 읽기 코드를 검토한 뒤 실행한다.

```sh
./dev env sync retry001
./dev exec retry001 train.py
```

마지막 명령은 원본이 `train.py`인 경우의 **재학습**이다. 다른 파일·인자를 썼다면 원본 기록대로 바꾼다. 저장한 모델을 그대로 평가할 때는 모델 읽기 코드를 사용하며, [최종 평가](final-evaluation.md)는 확정 계획 안의 모델 사본을 읽는다. 복원된 공통 코드 사본은 현재 공통 코드를 자동 교체하지 않는다. 환경이 다르다는 오류가 나오면 원래 환경을 먼저 맞추고, 새 환경으로 바꿔 실험할 때만 [잠금 갱신](development.md#개인-실험-패키지)을 사용한다.

## 전송 실패와 재시도

`./dev status`는 서버 응답을 기다리지 않고 로컬 전송 기록을 보여준다. 실제 서버의 현재 상태·실패 원인을 확인하거나 즉시 재전송할 때는 `./dev sync`를 사용한다.

`save()`는 로컬 저장을 완료하면 반환하며 서버에 접속하지 않는다. MLflow 연결을 설정한 Docker 작업 환경이 켜져 있으면 기본 60초 간격으로 미전송 결과와 **선택한 모델의 미완료 전송**을 처리한다. 완료한 전송은 건너뛴다. 서버·네트워크 연결이 끊겨도 다음 학습은 계속할 수 있으며, 연결이 복구되면 자동 전송을 다시 시도한다.

학습·저장이 끝난 뒤 환경을 꺼도 미전송 결과는 로컬에 남아 다음 시작 때 처리된다. 종료 전에 서버 반영까지 확인하려면 `./dev sync`를 실행한다. 로컬 저장 완료 메시지는 서버 전송 완료를 뜻하지 않는다.

즉시 전송하고 기본 결과 파일도 다시 검사하려면 다음을 실행한다. **`./dev sync`와 `./dev archive`는 서버 응답을 기다리는 명령**이다.

```sh
./dev sync
```

`재전송 대기: 0`, `확인 필요: 0`과 함께 `전송 완료` 또는 `기존 전송 완료` 개수를 확인한다. 모두 0이면 저장된 실행이 있는지 확인한다. 서버에서는 삭제되지 않은 실행의 `FINISHED`와 `sixletters.complete=true`로 기본 전송 완료를 확인한다.

자동 전송은 Docker 작업 환경의 기본 `Global/artifacts/`를 대상으로 한다. 다른 `--output-root`에 저장했거나 자동 전송기가 없는 환경에서 Python을 직접 실행했다면 `./dev sync --root "해당 결과 경로"`로 전송한다. 서버 연결 없이 저장한 결과도 연결 설정 후 전송할 수 있다. 같은 결과 폴더에서 재전송하면 기존 서버 실행을 재사용한다. 동일 실행의 복사본을 여러 장비에서 동시에 최초 전송하면 중복이 생길 수 있으므로 전송할 원본 위치를 하나로 유지한다.

`./dev sync`는 전송 개수와 함께 **실패한 이름·실험·실행 ID, 원인, 조치**를 표시한다. 자동 재전송 로그에도 실패 원인이 바뀌거나 전송이 복구되면 표시된다.

폴더를 읽을 수 없으면 `탐색 실패`와 결과 루트 기준 경로를 표시한다. `.`은 결과 루트 자체다. 그 경로 아래의 실행 개수·전송 여부는 확인하지 못한 상태이며, 읽을 수 있는 다른 결과는 계속 전송한다. 실패가 남아 있으면 명령은 실패 상태로 종료한다. 폴더의 소유자와 읽기·탐색 권한을 바로잡은 뒤 `./dev sync`를 다시 실행한다. 결과 폴더와 파일의 심볼릭 링크는 따라가지 않는다.

| 오류 코드 | 확인할 것 |
|---|---|
| `auth` | `.env`의 계정·비밀번호 |
| `permission` | 서버에서 해당 실험에 쓰기 권한이 있는지 |
| `local_permission` | 로컬 `Global/artifacts/`의 읽기·쓰기 권한 |
| `network` | 서버 실행 상태·네트워크/VPN·접속 주소 |
| `server` / `timeout` | 서버 오류 또는 응답 지연 |
| `locked` | 다른 프로세스의 전송이 끝날 때까지 대기 |
| `bundle_changed` | 저장 파일의 누락·변경 여부. 원본 복원 또는 새 실행으로 저장 |
| `remote_deleted` | 서버에서 삭제된 실행. 계속 공유하려면 관리자에게 해당 실행 복원을 요청한 뒤 `./dev sync` |
| `configuration` | 서버 주소·공동 실험 이름의 형식 |
| `unknown` | 재시도 후에도 반복되면 실행 ID를 기준으로 서버 관리자에게 확인 |

자동 전송은 완료 기록을 건너뛰므로 서버에서 나중에 삭제한 결과는 `./dev sync`로 확인한다. 삭제된 실행은 자동 복원하거나 새 실행으로 다시 올리지 않는다. 복원 전까지 재전송 대기로 표시하며, 다른 결과의 전송은 계속한다.

오류 원문 대신 확인 가능한 원인과 조치만 표시한다. `.env`를 수정했다면 진행 중인 학습과 저장을 마친 뒤 [환경을 종료하고 다시 생성](development.md#4-파일-보관과-환경-갱신)한다. 저장된 실행 폴더는 직접 수정하지 않고, 바꾼 학습은 새 실행으로 남긴다.
